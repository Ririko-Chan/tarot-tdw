# Аудит логики и полноты реализации (2026-04-06)

## Что уже соответствует плану

1. В колоде Rider-Waite действительно 78 карт и у каждой есть upright/reversed смысловые блоки с контекстами `general/relationships/career/advice`.
2. Реализованы базовые экраны: home, reading, settings.
3. Реализована генерация расклада с шансом перевёрнутой карты и шансом подсказки.
4. Есть пресеты раскладов (`free-1-24`, `horseshoe`) и фиксация `cardCount` для подковы.
5. Есть хранилище истории и базовые операции `save/delete/rename` на уровне репозитория.

## Что не хватает (по плану/требованиям)

1. **Нет пользовательского экрана истории в рабочем сценарии приложения**.
   - Есть `history-screen.js`, но он не подключён в `main.js`, перехода на экран нет.

2. **Нет UI для удаления и переименования записей истории**.
   - На уровне репозитория методы есть, но в интерфейсе нет кнопок/обработчиков.

3. **В историю не сохраняется часть обязательных данных**.
   - По плану нужна фиксация настроек вероятностей и выбранной колоды в каждой записи.
   - Текущий объект расклада не содержит snapshot настроек (`deckId`, `reversedChance`, `hintChance`) как отдельный блок для истории.

4. **Выбор колоды архитектурно только частично реализован**.
   - В настройках показывается только один вариант (`rider-waite`), а загрузчик колод принудительно откатывает любой другой id к дефолтной колоде.

## Логические ошибки и риски

1. **Некорректный путь к рубашке в meta.json**.
   - Указан `back.png`, но в ассетах колоды используется `back.webp`.
   - Это приведёт к 404, если поле `backImage` начнут использовать в UI.

2. **`ensureCardCount` не защищён от нечислового `cardCount`**.
   - Для свободного расклада используется `Math.min/max` с входным значением без явной нормализации.
   - При строке/NaN может вернуть `NaN`, что затем ломает выбор карт (пустой расклад).

3. **Слабая валидация спредов**.
   - `assertSpread` проверяет только `id` и `name`, но не проверяет тип/границы `cardCount`, длину `positions`, их согласованность.

4. **Тихая деградация по контексту**.
   - Если контекст введён вручную (fallback через `prompt`) и неверен, резолвер молча переключит на `general`.
   - Это не критичная ошибка, но создаёт "тихое" поведение без обратной связи пользователю.
