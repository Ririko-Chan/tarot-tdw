# Аудит логики и полноты реализации (2026-04-06)

## Что уже соответствует плану

1. В колоде Rider-Waite действительно 78 карт и у каждой есть upright/reversed смысловые блоки с контекстами `general/relationships/career/advice`.
2. Реализованы базовые экраны: home, reading, settings.
3. Реализована генерация расклада с шансом перевёрнутой карты и шансом подсказки.
4. Есть пресеты раскладов (`free-1-24`, `horseshoe`) и фиксация `cardCount` для подковы.
5. Есть хранилище истории и базовые операции `save/delete/rename` на уровне репозитория.

## Что не хватает (по плану/требованиям)

На текущий момент критические пункты из предыдущей версии аудита закрыты:
1. Экран истории подключён в основной навигации.
2. На экране истории добавлены UI-действия для удаления и переименования.
3. В объект расклада добавляется snapshot настроек и данные колоды.
4. Выбор колоды в настройках строится из реестра доступных колод (не захардкожен в UI).

## Логические ошибки и риски

1. **Некорректный путь к рубашке в meta.json — исправлено**.
   - Поле `backImage` указывает на существующий `back.webp`.

2. **`ensureCardCount` и нечисловой `cardCount` — исправлено**.
   - Добавлена явная нормализация к числу с fallback к `min`.

3. **Слабая валидация спредов — усилена**.
   - `assertSpread` теперь проверяет тип/диапазон `cardCount`, тип `positions` и согласованность длины с фиксированным количеством карт.

4. **Тихая деградация по контексту — снижена**.
   - В fallback-сценарии ввода теперь есть уведомление при невалидном контексте и явная подстановка `general`.
