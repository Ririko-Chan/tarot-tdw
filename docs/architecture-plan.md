# Architecture plan (tarot-tdw)

## 1) Что должно быть в приложении (функциональные требования)

### Расклад и ввод запроса
1. На главном экране пользователь выбирает количество карт (1..24).
2. После кнопки «Вытянуть» открывается модалка:
   - поле вопроса (обязательное),
   - выбор сферы кнопками: `отношения | карьера | общее | подсказка`.
3. После подтверждения запускается анимация появления карт рубашкой вверх и затем их переворот на лицевую сторону.
4. При клике на карту:
   - поверх карты показывается overlay с ключевыми словами и трактовкой по выбранной сфере.

### Логика карты
5. У каждой карты:
   - одна общая рубашка колоды,
   - индивидуальная лицевая сторона,
   - значения для `upright` и `reversed` с контекстами `general/relationships/career/advice`.
6. Поддерживается настраиваемый шанс перевёрнутой карты.

### Подсказка колоды
7. Поддерживается настраиваемый шанс «подсказки от колоды».
8. Если шанс сработал — показывается отдельная подсказка в итоге расклада.

### История
9. Сохранение расклада в историю с:
   - именем,
   - датой/временем,
   - вопросом,
   - сферой,
   - выбранной колодой,
   - настройками вероятностей,
   - выпавшими картами.
10. Удаление записи из истории.
11. Редактирование названия из истории.

### Колоды и расклады
12. В базе должно быть 78 карт для дефолтной колоды Райдера-Уэйта.
13. В настройках должна быть возможность выбора колоды (архитектурно уже сейчас).
14. Должны быть preset-расклады с фиксированными позициями (например, «Подкова»).
15. Дополнительно: поддержать режим ручного тасования/вытягивания в будущем (через отдельный feature-модуль).

## 2) Что должно быть в каких файлах

> Главный принцип: разделяем **контент**, **доменную логику**, **UI** и **хранилище**.

### Данные (легко редактировать контент)
- `src/data/decks/rider-waite/cards.json`
  - только массив карт и их значения;
  - без UI-логики и без случайностей.
- `src/data/decks/rider-waite/meta.json`
  - id колоды, название, путь к рубашке, описание.
- `src/data/spreads.json`
  - пресет-расклады: id, name, cardCount, positions.
- `src/data/hints.json`
  - текстовые подсказки от колоды.

### Доменная логика (чистые функции)
- `src/core/random.ts` (или `.js`)
  - `shuffle`, `rollChance`, генератор id, seed-поддержка при необходимости.
- `src/core/reading-engine.ts`
  - создание расклада из входных параметров;
  - выбор/ограничение количества карт;
  - назначение upright/reversed;
  - выбор подсказки.
- `src/core/meaning-resolver.ts`
  - выбор текста значения по сфере и ориентации карты;
  - возвращает структуру для overlay.
- `src/core/validators.ts`
  - проверки структуры данных карт, спредов, настроек.

### Фичи
- `src/features/readings/create-reading.ts`
  - orchestration: взять данные + engine => вернуть результат расклада.
- `src/features/history/history-repo.ts`
  - CRUD истории в localStorage/IndexedDB.
- `src/features/settings/settings-repo.ts`
  - хранение настроек вероятностей, выбранной колоды.
- `src/features/decks/deck-service.ts`
  - загрузка колоды по id, fallback к Rider-Waite.
- `src/features/spreads/spread-service.ts`
  - получение пресетов и валидация cardCount.

### UI
- `src/ui/screens/home-screen.ts`
  - выбор количества карт, кнопка «Вытянуть».
- `src/ui/components/pre-draw-modal.ts`
  - вопрос + сфера (обязательные поля).
- `src/ui/screens/reading-screen.ts`
  - рендер расклада (рубашки/позиции).
- `src/ui/components/tarot-card.ts`
  - flip-анимация одной карты.
- `src/ui/components/card-meaning-overlay.ts`
  - overlay по клику: карта + контекстная трактовка.
- `src/ui/screens/history-screen.ts`
  - список истории + удаление.
- `src/ui/screens/settings-screen.ts`
  - вероятность перевёрнутых, вероятность подсказки, выбор колоды.

### PWA
- `src/pwa/register-sw.ts`
- `src/pwa/sw-cache-config.ts`

### Входные точки
- `js/app.js`
  - инициализация приложения и роутинг экранов (пока можно оставить как адаптер к новой структуре).
- `js/tarot.js`
  - временный compatibility-layer (реэкспорт данных/функций), пока проект мигрирует.

## 4) Какие функции реализовать в первую очередь

### P0 (обязательно)
1. Рендер home + выбор количества карт (1..24).
2. Модалка вопроса/сферы перед вытягиванием.
3. Генерация расклада + upright/reversed chance.
4. Flip-анимация и overlay с контекстным значением.
5. Сохранение в историю + удаление записи.
6. 78 карт Rider-Waite как источник данных.

### P1
1. Preset-расклады (подкова и т.д.).
2. Настройки шанса подсказки и отображение подсказки.
3. Выбор колоды в настройках (готовность к нескольким колодам).

### P2
1. Ручное тасование/вытягивание (drag/gesture-сценарий).

## 5) Почему это будет легко редактировать

1. Тексты и значения карт лежат в `cards.json`, а не в UI-коде.
2. Любые новые колоды добавляются папкой `data/decks/<deck-id>/...`.
3. Изменение анимации не затрагивает смысловые данные карт.
4. Изменение трактовок не требует правок движка расклада.
5. Пресеты раскладов добавляются через `spreads.json`.
